一、本轮改了什么（只有 2 处，都是 iOS 侧的跨端破绽）
==================================================================

【改动 1】iOS 内隐藏「检查更新」入口
  文件：app/client/src/pages/settings/SettingsPage.tsx

  问题（已取证）：
    「检查更新」依赖前端原生插件 AppUpdater，而该插件只有安卓实现：
      安卓  mobile/android/app/src/main/java/com/playtostar/app/AppUpdaterPlugin.java  ✅
      iOS   mobile/ios/App/App/ 下只有 AppDelegate.swift / SceneDelegate.swift /
            WechatAuthPlugin.swift，无 AppUpdater 的任何 Swift 实现           ❌
    且 c52 包内 ios/App/App/capacitor.config.json 的插件注册表为：
      packageClassList = [SignInWithApple, AppPlugin, FilesystemPlugin,
                          SharePlugin, StatusBarPlugin]
    不含 AppUpdater。

  后果：
    iOS 上点「检查更新」→ checkForUpdate() → AppUpdater.getAppInfo()
      → Capacitor 抛 "plugin is not implemented on ios"
      → getCurrentAppInfo() 的 catch 吞掉并返回 null
      → checkForUpdate() 返回 null
      → 界面弹红字「暂时无法检查更新，请稍后再试」
    iOS 用户 / 审核员看到的是一个明确报错的功能项。

  修法：
    引入 isIosApp()（来自 @client/src/hooks/use-native-app），
    const showUpdateEntry = !isIosApp();
    菜单数组用条件展开：...(showUpdateEntry ? [{检查更新...}] : [])
    → iOS 壳内该项整体不渲染；安卓壳与网页端行为完全不变。
    → 说明：iOS 版本的更新由 App Store 自身负责，该项对 iOS 本就无意义。

【改动 2】崩溃兜底页的安卓 APK 下载链接在 iOS 内隐藏
  文件：app/client/src/index.tsx

  问题：
    ErrorBoundary 的 fallback 页面里有一个 <a> 指向
      https://playtostar.com/download/playtostar.apk
    文案「仍无法使用？下载最新版」+ 小字「直接覆盖安装（包名签名一致、保留数据）」。
    此处**没有** isNativeApp() 判断。
    对比：顶栏的 AppDownloadButton（Layout.tsx:66-68）早就有
      if (isNativeApp()) return null;  → 所以顶栏在原生壳内是安全的。
    这处属遗漏。

  为什么这处比改动 1 更该修：
    iOS 无法安装 .apk。若审核员遇到崩溃，屏幕上是
      「下载最新安装包」「包名签名一致、保留数据」
    这是全平台最直白的「这应用其实是安卓的」证据，正好撞在
    4.1(a) Copycats「同一产品的多端版本」的指控点上。
    触发概率低（要 React 渲染崩溃才会走到），但一旦出现后果更重。

  修法：
    {!isNativeApp() && ( <> 原 <a> + 小字说明 </> )}
    → 只在浏览器 / 安卓壳内显示；iOS 壳内完全不渲染。

七、遗留（本轮不处理，已知不影响审核）
==================================================================
  1. 安卓壳的「检查更新」仍指向 https://playtostar.com/download/version.json，
     该文件 apkUrl = https://playtostar.com/download/playtostar.apk，
     versionCode=45。安卓端功能正常，不动。
  2. AppUpdateGate 启动后 2.5 秒会调 checkForUpdate()，但在 iOS 上
     getCurrentAppInfo() 先返回 null 即 return，**不会去拉 version.json**，
     所以冷启动零异常、零多余请求。无需额外处理。
